    CORE ARCHITECTURE

    Built for Engineering Reality, Not Mockups

    Most coding agents treat frontend as decorative styling, leave backend endpoints disconnected, and forget the entire project when tokens expire. ForgeX solves this at the root.

    UI/UX as a Release Gate

    No generic purple gradients or repetitive rounded card slop. ForgeX enforces deliberate typography art direction, mobile viewport overflow assertions, mature light/dark tonal hierarchies, and accessible interaction states.

    • Six-part typography art direction protocol
    • Programmatic mobile overflow validation
    • Intentional light & dark tonal depth

    Cross-Stack Traceability

    Trace every feature through the entire chain: UI event → client request → route → server validation → persistence → error contract → reactive UI. Eliminates mismatched types and swallowed errors.

    • Strict server-side validation invariants
    • No hardcoded fake responses in production
    • Explicit loading, empty, and error UI states

    Session Handoff & Memory

    Context windows run out; ForgeX keeps working memory durable. By recording progress, decisions, verified tests, and next actions in WORK-STATE.md, subsequent agents pick up with zero rediscovery waste.

    • Token-efficient continuity across sessions
    • Preserves uncommitted Git changes safely
    • One canonical source of truth for the project

    VERIFICATION STANDARDS

    Strict Quality Gates. Evidence Over Claims.

    ForgeX holds coding agents to the same engineering rigor as human tech leads.

    Truthful Completion Language

    Distinguishes between implemented, tested, and verified. Never hallucinate test counts or claim "pixel-perfect" without observed browser evidence.

    Actual Viewport & Overflow Gates

    Mobile QA requires true CSS viewport evaluation (390×844). Enforces scrollWidth ≤ clientWidth + 1 to prevent horizontal clipping.

    Non-Destructive Git Safety

    Never automatically resets, cleans, or overwrites uncommitted working tree changes. Existing user modifications are tracked and preserved.

    Failing Honestly & Deliberate Recovery

    When a command or test fails, preserve its original output, diagnose the root cause, and retry with reason instead of blindly looping.
