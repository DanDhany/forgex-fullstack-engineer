01 / PROCESS

The 5-Step Engineering Pipeline

Instead of jumping blindly into editing, ForgeX guides the agent through five deliberate phases: recovering context, crafting responsive UI, tracing contracts across layers, gathering real proof, and persisting handoff memory.

Phase 01 • Recovery & Safety

Inspect Before Editing & Preserve User Work

When an agent blindly modifies files without checking Git, it risks wiping uncommitted user work or assuming obsolete framework versions. ForgeX reads WORK-STATE.md first, inspects Git status, and diagnoses the repository before making any code change.

✓ Checks git status --short --branch and preserves in-progress modifications.
✓ Resumes from established handoff file rather than wasting tokens on re-indexing.
✓ Verifies exact versions from lockfiles (Laravel, React, Node, Python).
✓ Scales planning depth directly proportional to task risk.

$ git status --short --branch
## main...origin/main

?? app/Services/StripeWebhook.php

Preserve all uncommitted user work.

Checkout idempotency flow. Zero blind rediscovery.
Phase 02 • Product Craft

Product-Aware Art Direction & Anti-Slop Gates

ForgeX treats UI/UX as a structural engineering discipline. It forbids agents from pasting generic SaaS templates, neon glows on dark navy, or squeezing desktop UI into mobile screens. Every substantial UI task requires a concrete design thesis before implementation.

✓ 6-Part Typography Gate: character, system, headline wrap, harmony, render check, state polish.
✓ Tonal Hierarchy: Designed light palettes (warm ivory/stone) & tiered dark surfaces, not flat black slabs.
✓ Mobile Overflow Gate: scrollWidth ≤ clientWidth validated across 320/360/390/430px.
✓ Complete interactive states: hover, focus-visible, active, disabled, error, loading.

Phase 03 • Integration

Cross-Stack Contracts: Trace UI to Database

A feature is not finished if the UI connects to a fake success mock, an outdated schema, or swallowed 500 errors. ForgeX traces the complete contract path across client and server boundaries before declaring completion.

✓ Full Pipeline Trace: UI Event → Client Request → Route → Auth → Validation → Domain Rule → DB Transaction → Response → UI State.
✓ Prohibits hardcoded production data, stale mocks, and swallowed errors.
✓ Handles loading, empty, validation, 401, 403, 429, and 500 error states.
✓ Enforces server-side validation and authorization policies.

Phase 04 • Evidence

Evidence Before Claims & Honest Limits

Agents frequently declare “I tested this and it works perfectly” without ever executing a test runner. ForgeX enforces evidence-first discipline: real test execution, real browser viewport validation, and honest reporting when tools are unavailable.

✓ Never fabricates test counts, screenshots, or tool outputs.
✓ Validates real viewports: mobile (320, 360, 390, 430), tablet (768), desktop (1280, 1440).
✓ Asserts actual CSS viewport dimensions, not scaled desktop crops.
✓ Marks missing browser tools as BLOCKED rather than faking success.

Phase 05 • Continuity

Durable Handoff via WORK-STATE.md

Token exhaustion and context switches break development momentum. ForgeX ends every non-trivial task by updating WORK-STATE.md with exact completed work, decisions made, verified outcomes, open blockers, and a ready-to-run resume prompt.

✓ Maintains one concise file: WORK-STATE.md (no duplicate timestamped clutter).
✓ Records uncommitted Git diff state and modified paths.
✓ Formulates the single next actionable step for the subsequent session.
✓ Reduces context window re-discovery token cost by up to 80%.

02 / COMPARISON

The Engineering Ledger: Drift vs Invariants

AI models generate competent code snippets, but stumble on product continuity and full-stack alignment. Here is how ForgeX replaces common agent failure modes with strict engineering contracts.

COMMON AGENT FAILURE MODES
FORGEX SYSTEMIC INVARIANT
× Context Window Amnesia

When the context window runs out, the replacement session starts blind. It re-indexes the entire repository, invents conflicting conventions, or overwrites working code.

✓ Durable Handoff via WORK-STATE.md

Maintains a structured, single handoff file documenting verified outcomes, touched files, open blockers, and the exact next action. A new agent resumes in 10 seconds.

× Generic "AI Slop" Design

Every generated page looks identical: centered hero, purple/blue neon glows on dark navy, unstyled light mode, and desktop cards overflowing off the screen on phones.

✓ Product-Aware Craft & Viewport Gates

Enforces a 6-part typography gate, designed light (warm ivory/stone) and dark palettes, and asserts scrollWidth ≤ clientWidth across 320, 360, 390, and 430px viewports.

× Disconnected Cross-Stack Contracts

The frontend interface looks complete, but calls an unvalidated endpoint, assumes hardcoded fake JSON, ignores database transactions, or silently swallows server errors.

✓ End-to-End Contract Release Gate

Features are traced from UI event → client state → validation → DB transaction → response schema → UI error boundary. Stale mocks are treated as release blockers.

× Hallucinated Verification

The agent confidently asserts “all tests passed and the UI looks great on mobile,” even though it never executed a test runner or inspected a rendered viewport.

✓ Evidence-First Guardrails

Requires observed command output and real browser tool validation. If tools are missing, the agent honestly reports the check as BLOCKED rather than fabricating success.

06 / VERIFIED ANSWERS

Frequently Asked Questions

Verified operational details regarding ForgeX installation, invocation, and safety guarantees.

Is ForgeX an npm package or an agent skill? +

ForgeX is a portable coding-agent skill containing a canonical SKILL.md and modular reference files. It is distributed via GitHub and installed directly using the Skills CLI (npx skills add ...) or the bundled Node.js installer (node ./bin/install.js). You do not need to install it as an application npm dependency.

Why does Codex use $forgex while others use /forgex? +

Different agent hosts have distinct skill discovery and invocation conventions. In OpenAI Codex CLI/IDE, typing $forgex explicitly attaches the skill to your prompt, and ForgeX explicitly disables implicit activation (allow_implicit_invocation: false) so it doesn't clutter unrelated tasks. In Claude Code and Antigravity, slash commands or skill pickers are supported. There is no universal slash command across every AI host.

What happens if browser automation (Playwright/Chrome) is not installed? +

Under ForgeX's Evidence-First Engineering rules, the agent will perform static source-code analysis and clearly report browser QA as BLOCKED / NOT RUN. It is strictly forbidden from claiming that visual checks passed or that screenshots were inspected when the required tooling is unavailable.

Will ForgeX overwrite my existing uncommitted Git modifications? +

No. Step 2 of the ForgeX workflow explicitly mandates running git status --short --branch, inspecting modified paths, and preserving user changes. ForgeX never runs automated hard resets, stashes, or checkouts that could destroy your in-progress work.

How do I uninstall ForgeX if I no longer need it? +

The bundled installer writes a .forgex-manifest.json in the destination directory. You can uninstall by running node ./bin/install.js --uninstall, or simply remove the forgex/ directory from your agent's skills folder (e.g. .agents/skills/forgex).
