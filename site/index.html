    HOW FORGEX WORKS

    Solves the Three Biggest Frustrations with Coding Agents

    Most agents build generic mockup templates, leave backend endpoints disconnected, and forget the entire project when the context window fills up. ForgeX fixes this.

    Responsive UI & Typography Art Direction

    Stops agents from assembling generic SaaS templates. Forces agents to select fonts that match the product, establish distinct light and dark tonal layers, and prove that mobile viewports have zero horizontal overflow before calling UI work done.

    Type: Plus Jakarta Sans + JetBrains Mono
    Themes: Obsidian Dark (#090D16) & Slate Light (#F8FAFC)
    Gate: scrollWidth ≤ clientWidth assertion on 390px

    End-to-End Contract Traceability

    Prevents agents from claiming a feature works while leaving a fake mock or an unhandled 500 error behind. Every change is traced from the user interaction through client state, server validation, database transaction, and UI feedback states.

    Client: Typed request & client-side validation guard
    Server: Strict validation rules & database transactions
    Reaction: Explicit loading, empty, and error UI states

    Durable Session Handoff (WORK-STATE.md)

    When context windows compress or sessions switch, agents usually forget active diffs and re-read the whole repository. ForgeX writes a structured handoff with touched files, test results, and the single next action so the next session resumes immediately.

    Safety: Never cleans or overwrites uncommitted git diffs
    File: One canonical WORK-STATE.md file updated in place
    Token Cost: ~400 tokens to resume vs re-indexing repo

    OPERATIONAL RULES

    Four Rules Every Agent Must Follow

    Clear guidelines that prevent coding agents from fabricating test results or breaking working trees.

    Evidence Before Claims

    Distinguishes between implemented, tested, and verified. The agent must never claim "all tests passed" or "pixel-perfect" without observed tool evidence.

    Mobile Viewport Overflow Gate

    Requires checking actual mobile CSS viewports (390×844). Enforces scrollWidth ≤ clientWidth + 1 to prevent horizontal clipping.

    Non-Destructive Git Safety

    Never resets, cleans, or overwrites uncommitted working tree files. Existing user modifications are tracked and preserved before making changes.

    Honest Failure Recovery

    When a command or test fails, the agent must preserve the original error output, diagnose the root cause, and retry with reason instead of blindly looping.
